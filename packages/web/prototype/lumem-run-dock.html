O rodapé de execução

O Lumem cria worktrees que não rodam: nascem sem dependência, sem build e sem nenhum lugar no produto onde subir a aplicação e ver a mudança de pé. Esta tela é a segunda metade da feature project-scripts — a primeira é uma tabela [scripts] no <repo>/.lumem/project.toml, que já existe e hoje só guarda o id do projeto.

Sete quadros. O primeiro e o segundo são as duas leituras da S1 — o rodapé na coluna da direita ou atravessando o painel central. Os outros cinco são os estados que o §9 do PRD pediu.

1 · o rodapé embaixo da árvore

S1 · proposta A associação que a imagem de referência faz: o repositório em cima, o que ele faz quando roda embaixo. Quatro abas que são a mesma primitiva — sessão com terminal —, e o que muda entre elas é só quem escolheu o comando: o project.toml nas três primeiras, você na última.

Testes entrou por uso, depois das outras: rodar a suíte é a coisa que mais se repete num dia de trabalho, e ela estava fora do produto — quem quisesse testar abria um terminal e digitava o comando de novo, toda vez. O ponto na aba responde "passou?" sem ninguém precisar abrir.

E o rodapé nasce ocupando metade da janela, não uma tira no pé dela: a primeira versão tinha 256px fixos, e a primeira coisa que se fazia ao abrir era arrastar.

O custo, e é ele que está desenhado aqui: com o rodapé aberto, o teto de largura da coluna sobe. Um terminal de 80 colunas não cabe em 360px, e uma coluna que não cabe é uma coluna que ninguém usa duas vezes.

O ponto na aba, e não dentro dela. verde no Run é "tem coisa de pé"; no Setup é "a última passou". As duas perguntas que trazem alguém até aqui são exatamente essas, e escondê-las dentro da aba obrigaria a abrir para descobrir — o mesmo motivo pelo qual o contador de Mudanças mora na aba.

S6 “porta lida da saída” não é decoração. A porta pode vir de dois lugares — da variável LUMEM_RUN_PORT, que é determinística, ou de uma regex na saída, que acerta o Vite e erra o resto. Um botão que abre a porta errada é pior que não ter botão, então ele diz de onde tirou o número.

2 · a alternativa: o rodapé no painel central

S1 · alternativa O mesmo componente, atravessando a largura toda, abaixo da conversa. Cabe sem negociar pixel nenhum — e paga com a associação: o run deixa de estar junto da árvore de arquivos, que é o que fazia o quadro anterior se explicar sozinho. Aqui a coluna da direita fica nos 360px de sempre.

3 · Setup — o que termina

Setup e run não são a mesma coisa, e a diferença é o fim. Setup termina: o que interessa dele é o código de saída e quando foi. Run não termina: o que interessa é estar vivo. Por isso esta aba tem histórico e a outra tem estado.

5 · o projeto sem [scripts]

Este é o estado normal, não o excepcional: todo projeto entra no Lumem assim. E é a única superfície do produto onde alguém descobre que esse arquivo existe — então o vazio ensina, com o texto pronto para colar e o caminho exato onde ele mora.

o vazio que ensina
Este projeto não diz como rodar.

O Lumem lê os comandos de um arquivo do repositório, versionado junto com o código: quem clonar depois herda o mesmo setup, com Lumem ou sem. Enquanto ele não existir, as abas Setup e Run ficam vazias — o Terminal continua funcionando.

.lumem/project.toml
# o id já está aqui; o que falta é o resto id = "prj_7f3a1c…" [scripts] setup = "./scripts/setup.sh" run = "pnpm dev" test = "pnpm test" teardown = "./scripts/teardown.sh"

O gesto principal é pedir para o agente, e não escrever um arquivo de exemplo. Um run = "pnpm dev" chutado pelo produto está errado na maioria dos repositórios; quem consegue ler o package.json, o Makefile e o docker-compose.yml antes de responder é o agente. O clique abre uma conversa nova já com o pedido dentro — as três fases, o que cada uma significa, e a instrução de ler o repositório antes de inventar. O arquivo aparece como mudança comum na aba Mudanças, para você revisar e commitar.

Sem agente conectado, o botão fica desabilitado com o motivo ao lado — o mesmo padrão do remover workspace. E copiar o exemplo continua ali para quem prefere escrever à mão.

6 · recolhido — e o run visto de fora

O rodapé pode estar fechado, ou você em outra worktree. Sem sinal fora dele, “tem um dev server de pé aqui” vira coisa que só o lsof sabe — e a próxima vez que você rodar, a porta já está ocupada por você mesmo.

7 · a primeira execução de um projeto que veio de uma URL

S11 · segurança Desde a project-from-url, um projeto entra no Lumem a partir de uma string colada. Somado ao setup automático, colar uma URL passaria a significar executar um script de um estranho. Então o [scripts] de um projeto recém-clonado nasce não confiado: a primeira execução é sempre um gesto, com o comando visível.

o comando aparece antes de virar processo
⚠Este comando vem do repositório, não de você.

lorebase foi clonado de github.com/outra-pessoa/lorebase há 2 minutos. O que está escrito abaixo estava dentro dele, e vai rodar na sua máquina com as suas permissões.

./scripts/bootstrap.sh --with-secrets
“confiar” vale para este projeto nesta máquina — e volta a perguntar se o comando mudar.

O que isto não protege: um script que você aprovou faz tudo que você faria. Sandbox de execução é outro problema, e ele está no backlog — não escondido atrás desta tela.
